# bootstrap

Run-once root configuration, applied from a laptop. It creates the resource group, the network (via `../modules/network`), the Stack's managed identity and federated credentials, the HCP Terraform project, agent pool, variable set and Stack, a budget, and the HCP Terraform agent VM.

## Prerequisites

- `az login` and `az account set --subscription <id>` (you need Owner on the subscription).
- `TFE_TOKEN` exported (HCP Terraform user or team token).
- An existing public Azure DNS zone (the parent zone). Bootstrap creates a delegated child zone `<lab_subdomain>.<zone>` in the lab resource group and adds one NS record for it in your parent zone, using your laptop credentials.
  - Your `az login` needs DNS Zone Contributor on the parent zone, in whichever subscription it lives.
  - If the parent zone is in another subscription, set `public_dns_zone_subscription_id`.
  - If it is in another tenant, set `create_lab_delegation = false`, apply, then add the NS record by hand with the child zone's name servers (output `lab_dns_zone_name_servers`):

    ```bash
    terraform output -json lab_dns_zone_name_servers
    az network dns record-set ns create -g <parent-zone-rg> -z <parent zone> -n <lab_subdomain> --ttl 300
    az network dns record-set ns add-record -g <parent-zone-rg> -z <parent zone> -n <lab_subdomain> -d <name-server>   # once per name server
    ```
- A TFE `.hclic` licence file.

## Usage

```bash
cp terraform.tfvars.example terraform.tfvars   # fill in; the file is git-ignored
terraform init && terraform apply
```

## Optional: demo VPN

Set `enable_demo_vpn = true` to add a point-to-site VPN gateway and a DNS Private Resolver inbound endpoint in the lab VNet (off by default; about A$0.65/h while on; the gateway takes 30 to 45 minutes). Then run `scripts/demo-vpn-profile.sh` to build the Mac profile. Steps are in [docs/runbook.md](../docs/runbook.md#demo-access-through-vpn-optional). The inputs and outputs below are generated by terraform-docs; CI checks only `modules/*`.

## Warnings

- DNS blast radius: the agent VM identity can write only to the delegated lab subdomain zone (DNS Zone Contributor on the child zone). It has no role on your parent zone, so runs on the agent cannot change your other records. Inside the VNet, the private zone of the same name overrides resolution (split horizon).
- Local state contains secrets (agent token, licence, SSH key). Keep `terraform.tfstate` off shared drives and never commit it.
- Destroy order: destroy the Stack deployment first, then run `terraform destroy` here. `operator_cidrs` must still match your current IP when you destroy.
